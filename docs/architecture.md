# Архитектура

Схемы рендерятся GitHub (Mermaid). Решения и причины — в `decisions.md`.

## Компоненты

```mermaid
flowchart LR
    subgraph device["Телефон (Flutter)"]
        ui["Экраны: View + ViewModel (Riverpod)"]
        norm["Расчёт нормы и целей приёмов пищи"]
        local[("SQLite (drift): профиль, дневник")]
        ui --> norm
        ui --> local
    end

    subgraph server["Сервер (Spring Boot, Kotlin)"]
        api["recommendation · intake: REST API"]
        admin["admin: Thymeleaf + форма входа"]
        optimizer["optimizer: перебор с отсечением"]
        cache["Кэш лучших наборов (Caffeine)"]
        catalog["catalog: меню, точки, импорт CSV"]
        geo["geo: поиск рядом"]
        ocr["OCR-воркер (Tesseract)"]
        api --> cache --> optimizer
        api --> geo
        api --> catalog
        admin --> catalog
        ocr --> catalog
    end

    db[("PostgreSQL + PostGIS")]
    s3[("S3-хранилище фото (SeaweedFS)")]

    ui -- "цель, теги исключения, координаты (без идентификатора пользователя)" --> api
    catalog --> db
    geo --> db
    api -- "фото меню" --> s3
    ocr --> s3
```

Профиль, норма и дневник не покидают устройство. На сервер уходит только цель приёма пищи и место поиска.

## «Подобрать рядом»

```mermaid
sequenceDiagram
    actor U as Пользователь
    participant A as Приложение
    participant C as ComboSearchService
    participant G as NearbyVenueRepository
    participant K as Кэш наборов
    participant O as ComboOptimizer

    U->>A: «Подобрать рядом»
    A->>C: POST /api/v1/combos/search (цель, координаты, радиус)
    C->>C: округлить цель внутрь окна пользователя
    C->>G: точки с меню в радиусе (GiST-индекс)
    G-->>C: точки с меню в радиусе, ближайшие первыми
    loop для каждой точки
        C->>K: ключ = меню + версия меню + цель
        alt нет в кэше
            K->>O: лучшие наборы из 1–3 блюд
            O-->>K: наборы с объяснением
        end
        K-->>C: наборы
    end
    C-->>A: 3–5 вариантов с учётом расстояния, appliedTarget
    A-->>U: карточки наборов
```

## Жизненный цикл данных о блюде

```mermaid
stateDiagram-v2
    [*] --> ВПродаже: импорт CSV сети (A) или модерация фото (B)
    ВПродаже --> НаПерепроверке: жалобы трёх разных людей
    НаПерепроверке --> ВПродаже: модератор подтвердил или исправил (B)
    НаПерепроверке --> Снято: модератор снял
    ВПродаже --> Снято: нет в новом CSV сети
    Снято --> ВПродаже: снова есть в CSV
```

Каждое изменение повышает версию меню сети или точки, поэтому кэш наборов не отдаёт устаревший ответ.

## Время подбора от размера меню

Медиана по 5 случайным меню каждого размера, 9 замеров после прогрева (`ComboOptimizerPerformanceTest`, данные — `reports/optimizer-timing.csv`). Бюджет — 100 мс.

```mermaid
xychart-beta
    title "Медиана времени подбора, мс"
    x-axis "Позиций в меню" [25, 50, 100, 150, 200, 250]
    y-axis "мс" 0 --> 12
    line [0.08, 0.24, 0.47, 1.32, 4.11, 5.99]
```

| Позиций в меню | 25 | 50 | 100 | 150 | 200 | 250 |
|---|---|---|---|---|---|---|
| Медиана, мс | 0,08 | 0,24 | 0,47 | 1,32 | 4,11 | 5,99 |
| 90-й перцентиль, мс | 0,13 | 0,34 | 0,68 | 2,15 | 4,70 | 10,17 |

Рост сверхлинейный (число сочетаний до трёх блюд растёт как n³), но отсечение по калориям и куча фиксированного размера держат 250 позиций на порядок ниже бюджета.
