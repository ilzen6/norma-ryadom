# Как показать код: где что лежит, как запустить, как работает

Памятка для показа проекта преподавателям: что открыть, чем запустить и что рассказать.

## 1. Где лежит код

- На компьютере: папка `~/Downloads/norma-ryadom`.
- На GitHub: https://github.com/ilzen6/norma-ryadom (ветки `main` и `develop`).

| Папка | Что внутри | Чем открывать |
|---|---|---|
| `server/` | Сервер на Kotlin + Spring Boot | IntelliJ IDEA |
| `app/` | Мобильное приложение на Flutter | VS Code (или Android Studio) |
| `contract/` | Общие эталоны клиента и сервера: `openapi.json`, `norm-cases.json`, `combo-cases.json` | любой редактор |
| `e2e/` | Сквозные тесты Playwright (TypeScript) | VS Code |
| `tool/` | Скрипты подготовки данных на Python: меню сетей, точки из OpenStreetMap, карта, документы | VS Code |
| `docs/` | Документация: описание проекта, обзор стека, решения, тесты | любой редактор |

## 2. Правила кода, которые соблюдены

- Комментариев в коде нет ни в одном языке: Kotlin, Dart, SQL, YAML, Gradle, HTML, TypeScript. Все пояснения вынесены в `docs/`.
- Интерфейс, сообщения об ошибках и названия тестов — на русском; имена классов и переменных — на английском.
- Тексты приложения лежат только в `app/lib/l10n/app_ru.arb`, тексты админки — в шаблонах и `messages.properties`.
- Версии всех зависимостей точные.
- Проверки стиля и анализаторы (ktlint, detekt, `flutter analyze`) запускаются в CI на каждый push и проходят без замечаний.

## 3. Сервер в IntelliJ IDEA

**Открыть:** File → Open → выбрать папку `server` (в ней `build.gradle.kts`) → Trust Project. IDEA сама импортирует Gradle. Если попросит JDK — выбрать или скачать **Temurin 21** (File → Project Structure → SDK).

**Что показать в коде:**

| Файл | Что в нём |
|---|---|
| `src/main/kotlin/ru/normaryadom/NormaRyadomApplication.kt` | Точка входа |
| `optimizer/ComboOptimizer.kt`, `ComboScorer.kt`, `MealStructure.kt`, `ComboDiversifier.kt` | Алгоритм подбора: перебор с отсечением, оценка набора, правила состава, разнообразие выдачи |
| `recommendation/ComboSearchService.kt` | Сценарий «подобрать рядом»: найти точки → посчитать наборы → отсортировать с учётом расстояния |
| `geo/NearbyVenueRepository.kt` | Геозапрос PostGIS: точки в радиусе |
| `catalog/persistence/MenuItemRepository.kt`, `VenueRepository.kt` | Импорт «вставить или обновить» без дублей (`ON CONFLICT`) |
| `catalog/demo/DemoCatalogLoader.kt` | Загрузка демо-каталога при старте |
| `intake/report/ItemReportService.kt` | Жалобы на блюдо и перевод на перепроверку |
| `intake/ocr/OcrWorker.kt` | Распознавание фото меню (Tesseract) |
| `web/ApiExceptionHandler.kt` | Единый формат ошибок Problem Details |
| `src/main/resources/db/migration/V1…V5` | Схема базы (миграции Flyway) |
| `src/test/.../architecture/ArchitectureTest.kt` | Тест, который проверяет границы модулей |

**Запустить:**

1. Запустить Docker Desktop.
2. В терминале в корне проекта поднять только базу и хранилище:

   ```bash
   docker compose up -d db storage storage-init
   ```

   Если раньше поднимался весь стек (`docker compose up -d`), остановить контейнер сервера, чтобы освободить порт 8080: `docker compose stop server`.
3. Запустить сервер одним из двух способов:
   - **Через терминал IDEA** (вкладка Terminal, папка `server`):

     ```bash
     set -a; source ../.env; set +a; ./gradlew bootRun
     ```

   - **Кнопкой Run:** открыть `NormaRyadomApplication.kt` → зелёный треугольник у `fun main` → Modify Run Configuration → Environment variables → вставить строки из файла `.env` из корня проекта. Профиль `demo` задаётся там же (`SPRING_PROFILES_ACTIVE=demo`): при первом старте загрузятся 14 285 заведений и меню сетей.
4. Проверить:
   - Swagger (все запросы API): http://localhost:8080/swagger-ui.html
   - Админка: http://localhost:8080/admin — логин `admin`, пароль в файле `.env.admin-password`.
   - Здоровье сервера: http://localhost:8080/actuator/health

**Тесты сервера:** `cd server && LANG=C.UTF-8 ./gradlew check` (нужен Docker: тесты сами поднимают PostgreSQL и хранилище). В IDEA можно открыть любой тест и нажать зелёный треугольник.

## 4. Приложение в VS Code

**Открыть:** File → Open Folder → папка `app`. Поставить расширения **Flutter** и **Dart**. Указать Flutter 3.47.6: Cmd+Shift+P → «Flutter: Change SDK» → `~/develop(flutter)/flutter-3.47.6`.

**Что показать в коде:**

| Файл | Что в нём |
|---|---|
| `lib/main.dart`, `lib/app.dart` | Точка входа, тема, навигация |
| `lib/domain/nutrition/norm_calculator.dart` | Расчёт нормы (Миффлин — Сан Жеор, 30/30/40) |
| `lib/domain/nutrition/meal_planner.dart` | Цели приёмов пищи |
| `lib/ui/home/home_view_model.dart` + `home_screen.dart` | Главный экран: состояние (ViewModel на Riverpod) и вид |
| `lib/data/repositories/combo_repository.dart` | Запрос подбора, расширение радиуса, если рядом мало вариантов |
| `lib/data/local/app_database.dart` | Локальная база SQLite (профиль, дневник, настройки) |
| `lib/data/demo/demo_engine.dart`, `demo_server.dart` | Офлайн-режим: тот же алгоритм подбора на Dart |
| `lib/routing/app_router.dart` | Экраны и переходы |
| `lib/l10n/app_ru.arb` | Все тексты интерфейса |

**Подготовка (один раз):**

```bash
cd app
flutter pub get
dart run build_runner build --delete-conflicting-outputs
```

**Запуск** (в VS Code — вкладка Run and Debug, выбрать готовую конфигурацию; или командой в терминале):

| Режим | Команда |
|---|---|
| Без сервера, встроенный каталог (проще всего) | `flutter run --dart-define=DEMO_SERVER=true --dart-define=TILE_URL_TEMPLATE=` |
| iOS-симулятор с локальным сервером | `flutter run --dart-define=API_BASE_URL=http://localhost:8080` |
| Android-эмулятор с локальным сервером | `flutter run --flavor demo --dart-define=API_BASE_URL=http://10.0.2.2:8080` |
| Браузер Chrome с локальным сервером | `flutter run -d chrome --dart-define=API_BASE_URL=http://localhost:8080` (в `.env` в `CORS_ALLOWED_ORIGINS` должен быть адрес страницы) |

Перед запуском на симуляторе: `open -a Simulator`.

**Тесты клиента:** `flutter analyze --fatal-infos && flutter test`.

## 5. Как всё работает

1. **Телефон считает норму сам.** По полу, возрасту, росту, весу, активности и цели — формула Миффлина — Сан Жеора, затем доли белков, жиров и углеводов 30/30/40. Норма делится на приёмы пищи (завтрак 25%, обед 35%, ужин 30%, перекус 10%). Личные данные никуда не отправляются: профиль и дневник лежат в SQLite на телефоне.
2. **На сервер уходит только цель приёма пищи**, координаты и исключённые продукты (например, «без свинины»). Ни имени, ни идентификатора пользователя.
3. **Сервер ищет заведения рядом** одним запросом PostGIS с геоиндексом, затем для каждого меню подбирает наборы из 1–3 блюд. Лучшие наборы кэшируются по версии меню.
4. **Алгоритм** перебирает сочетания с отсечением: калории в окне цели ±10%, белка не меньше минимума, жиров и углеводов не больше максимума, без исключённых продуктов. Не больше одного основного блюда и одного напитка, соус — только к еде. Наборы оцениваются по близости к цели; данные из ненадёжных источников получают штраф.
5. **Ответ** — список наборов с КБЖУ, ценой, расстоянием и уровнем достоверности. Если рядом мало вариантов, приложение само расширяет радиус: 1,5 → 3 → 6 км.
6. **Без сервера** (демо-APK и сборка для iPhone) тот же алгоритм работает в приложении на Dart по встроенному каталогу. Что он даёт те же ответы, что и сервер, проверяет контрактный тест по общему эталону `contract/combo-cases.json`.

## 6. Откуда данные и как проверяется их актуальность

**Заведения — из OpenStreetMap** (14 285 мест в Москве, области и Петербурге):

- берутся только места, которые в OSM правили или подтверждали за последние 3 года;
- явно закрытые отбрасываются (пометки `disused:` и `was:`, `opening_hours=closed`, дата закрытия, «закрыто» в названии);
- массовые автоматические правки не считаются подтверждением, что место работает;
- закрытые и переименованные сети отмечены отдельно (`tool/demo/chain_status.json`), например Subway;
- дата подтверждения хранится у каждой точки (`confirmed_on`) и видна в карточке заведения;
- пользователь может нажать «Заведение закрыто или переехало?». После трёх сообщений точка уходит на проверку, модератор в админке закрывает её, и повторная загрузка данных уже не вернёт её.

**Меню с КБЖУ — только из официальных источников сетей** (25 сетей, 3682 блюда):

- сайты, API приложений и опубликованные таблицы самих сетей; для каждой сети в `tool/menus/` есть скрипт разбора и отчёт с адресом источника, датой и списком отброшенных строк;
- при разборе калории сверяются с белками, жирами и углеводами (4·Б + 9·Ж + 4·У); строки, где цифры не сходятся, отбрасываются;
- если сайт даёт значения на 100 г, они пересчитываются на вес порции; берутся только порции на одного (без сетов, тортов целиком, больших пицц);
- у каждого блюда хранятся источник и дата («данные сети · проверено 13.08.2024»);
- кнопка «Цифры не совпадают»: после трёх жалоб блюдо скрывается из подбора до проверки модератором;
- фото меню от пользователей распознаются Tesseract и попадают в каталог только после проверки модератором;
- обновление — повторный запуск скрипта: импорт обновляет блюда без дублей, пропавшие из меню снимаются с продажи, версия меню растёт, и кэш сбрасывается автоматически.

**Достоверность видна на карте** в режиме «По данным»: зелёный — официальная таблица сети, жёлтый — меню с фото после модерации, красный — оценка, серый — данных нет.

## 7. Что в работе и что планируется

- **Типовые меню с примерными КБЖУ** для заведений без опубликованного меню: кофейни, пекарни, пиццерии, суши, шаурма, столовые. Значения — медианы официальных КБЖУ таких же блюд из наших сетей, с пометкой «оценка». Это в разы увеличит число вариантов рядом.
- **Магазины с готовой едой** (ВкусВилл, Азбука Вкуса) — если их данные будут доступны.
- **Больше городов:** выгрузка точек и карты из OpenStreetMap для других регионов.
- **Регулярное обновление меню** по расписанию в CI и отчёт о том, что изменилось.
