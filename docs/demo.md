# Сценарий демонстрации на защите

По разделу 16 документа. Время — 7–10 минут. Все шаги один в один проверяет `e2e/tests/app.demo-scenario.spec.ts`, скриншоты каждого шага — в `screenshots/`.

## Подготовка (до защиты)

1. Поднять сервер с демо-каталогом (6 вымышленных сетей в Москве, 12 точек):
   ```bash
   (cd server && ./gradlew bootJar)
   docker compose up -d --build --wait
   ```
   Переменные — по README, профиль `demo` уже выбран в `.env.example`.
2. Приложение на Android — один из вариантов:
   - готовый демо-APK из Releases — по инструкции `install-phone.md` (сервер на ноутбуке, телефон в той же сети Wi‑Fi);
   - своя сборка: `cd app && flutter build apk --release --flavor demo --dart-define=API_BASE_URL=http://127.0.0.1:8080`.

   Установить и пробросить порт сервера на телефон или эмулятор:
   ```bash
   adb install -r app-release.apk
   adb reverse tcp:8080 tcp:8080
   ```
   Адрес сервера меняется в приложении: Профиль → «Сервер». Демо-сборка разрешает HTTP к компьютеру в локальной сети, сборка `store` — только HTTPS (кроме `127.0.0.1`, `localhost` и `10.0.2.2`).
3. Геолокация эмулятора: Extended controls → Location → `55.7495, 37.5374` (Москва-Сити). Без неё можно отказать в доступе и выбрать район «Москва-Сити» — подбор пойдёт от центра района.
4. Если приложение уже открывали: Профиль → «Удалить все данные», чтобы начать с онбординга.
5. Админка: http://localhost:8080/admin, логин и пароль — те, чей bcrypt-хеш в `.env`.

## Демонстрация

1. **Онбординг.** Женщина, 25 лет, 165 см, 62 кг, умеренная активность, цель — похудение → норма 1800 ккал с объяснением под ней: базовый обмен по Миффлину — Сан Жеору 1365 ккал, с активностью (×1,55) — 2116 ккал, с целью (×0,85) — 1800 ккал. Показать «Изменить вручную»: ниже безопасного минимума 1200 ккал норму не задать.
2. **Предпочтения и геолокация.** «Без свинины», разрешить геолокацию.
3. **Главный экран.** «Осталось на сегодня: 1800 ккал, белок 99 г»; выбран «Обед» — цель ≈ 630 ккал ± 63. «Подобрать рядом» → 3–5 вариантов в разных сетях с суммой КБЖУ, расстоянием и ценой; свинины нет ни в одном.
4. **Набор.** Открыть вариант: по каждому показателю — значение, цель и отклонение. «Заменить» напиток → список замен, выбрать — набор пересчитан. «Записать в дневник» → дневник: прогресс по калориям, белкам, жирам и углеводам сдвинулся.
5. **Карта.** Зелёные (есть набор под цель) и жёлтые (компромисс) точки, легенда словами. Открыть «Гриль Хаус, Москва-Сити»: меню отсортировано по близости к цели, пометки «подходит / можно, но… / не подходит» с причиной, значки достоверности (данные сети с датой проверки, из меню заведения, оценка с диапазоном). «Собрать обед здесь».
6. **Обратная связь.** На блюде — «Цифры не совпадают» с причиной. Значок камеры → загрузить фото меню.
7. **Админка.** Модерация фото: фото, распознанный Tesseract текст, перенос строк в меню заведения — блюдо появляется в API с уровнем B. Жалобы: блюдо после жалоб трёх разных людей снято с подбора, модератор исправляет цифры.

## Вероятные вопросы

- **Почему не MapKit?** Ключ и отсутствие веб-сборки, на которой построены сквозные проверки; запасной план из документа — `flutter_map`, экран карты от поставщика тайлов не зависит (`decisions.md`).
- **Почему перебор, а не решатель?** 1–3 блюда из сотен позиций — перебор с отсечением точен, объясним и укладывается в миллисекунды; совпадение с полным перебором доказано проверкой свойств. Решатель — путь к подбору из нескольких заведений и 4–5 блюд.
- **Где персональные данные?** Только на устройстве; на сервер уходит цель без идентификатора пользователя. Жалобы хранят не IP, а HMAC-отпечаток.
- **Как не отдать устаревший подбор?** Ключ кэша содержит версию меню, любое изменение блюда её повышает (проверено тестом).
